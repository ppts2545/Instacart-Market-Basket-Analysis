# Data Setup Guide

## Overview

This project supports **two data modes**:

| Mode | Data Size | Use Case | Status |
|------|-----------|----------|--------|
| **Sample** (`USE_SAMPLE = True`) | ~10K lines | Quick testing & development | ✓ Pre-loaded in git |
| **Full Dataset** (`USE_SAMPLE = False`) | ~33M lines | Production analysis & reporting | Requires download |

## Sample Mode (Recommended for Testing)

Sample data is **pre-committed** in the repository. Use this for:
- Testing notebook logic
- CI/CD validation  
- Quick feature development
- Low-bandwidth environments

**Files included:**
```
data/raw/*_sample.csv
data/processed/**/*_sample.csv
```

**To use sample mode:**
```python
# In any EDA notebook (02_Exploratory_Data_Analysis/), set:
USE_SAMPLE = True
```

## Full Dataset Mode (Production Analysis)

Full Instacart dataset contains ~33M order lines across ~200K users.

### Step 1: Download Data

Download from **Kaggle**: https://www.kaggle.com/c/instacart-market-basket-analysis/data

Requires free Kaggle account.

### Step 2: Place in data/raw/

Extract CSV files to `data/raw/`:

```
data/raw/
├── aisles.csv
├── departments.csv
├── order_products__prior.csv
├── order_products__train.csv
├── orders.csv
├── products.csv
└── *_sample.csv (sample versions, already in git)
```

### Step 3: Run Quality Pipeline (Optional)

Pre-process and validate data:

```bash
python scripts/run_data_quality.py
```

This generates cleaned datasets in `data/processed/quality/`

### Step 4: Switch Notebooks to Full Data

In any EDA notebook (02_Exploratory_Data_Analysis/), set:

```python
USE_SAMPLE = False
```

Then run all cells. Notebooks will automatically load the full dataset.

## Data Files NOT in Git

By design, large CSV files are **NOT committed** to version control:

```
.gitignore rules:
data/raw/**      (ignore all raw CSVs)
data/processed/**  (ignore all processed CSVs)

EXCEPT:
*_sample.csv     (sample versions are committed)
```

**Why?**
- Large files bloat git history
- Violates data privacy best practices  
- Makes cloning slow
- Easy to regenerate from source

## FAQ

**Q: Can I run the notebooks without downloading data?**  
A: Yes! Use `USE_SAMPLE = True` (the default). Sample data is already in git.

**Q: Will results differ between sample and full data?**  
A: Yes. Sample (2 weeks) shows different patterns than full data (3 years).  
Use sample for development, full for production reporting.

**Q: How do I know which notebooks support switching?**  
A: Check the markdown title cell. EDA notebooks explicitly note:
```
Data Mode Configuration:
- Set USE_SAMPLE = False for full dataset
- Set USE_SAMPLE = True for sample testing
```

**Q: What if I can't download from Kaggle?**  
A: Use sample mode (`USE_SAMPLE = True`). It's sufficient for:
- Understanding analysis patterns
- Validating logic  
- Seeing final report structure
- Sharing on GitHub (no download required)

**Q: Can I version control only outputs, not raw data?**  
A: Yes! Notebooks (output) are version-controlled. CSVs (inputs) are not.  
This preserves git integrity while keeping code/results visible.

## Troubleshooting

### "FileNotFoundError: data/raw/orders.csv not found"

**Solution:** Download the Instacart dataset and place in `data/raw/`, OR set `USE_SAMPLE = True`

### "Memory error loading full dataset"

**Solution:** 
- Use sample mode: `USE_SAMPLE = True`
- Or use a machine with ≥8GB RAM
- Or process data in chunks (see scripts/)

### "How do I reset to sample data?"

**Solution:** Git ignores CSVs, so they're already separate:
```bash
# Remove any full data files you downloaded
rm data/raw/*.csv

# Keep sample files (already in .gitkeep or *_sample.csv)
```
